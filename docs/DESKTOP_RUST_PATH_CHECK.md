# デスクトップ版 Rust 経路の実機確認（チェックリスト）

対象: Windows / Linux のデスクトップ版。読取（REST）とチャット（WebSocket）を Rust 経由にしたときの確認。
Rust 経路は既定で有効。従来の経路に戻すには、下の「有効化・無効化」の手順を使う。

## 有効化・無効化

Windows / Linux のデスクトップ版では、読取（REST）とチャット（WebSocket）の Rust 経路が**既定で有効**。
ブラウザ・Android・macOS は従来の経路のまま。

確認するだけなら手順はない。アプリを起動し、次の2行が Console に出ていれば Rust 経路で動いている:

- `[disnans] api read transport: tauri`
- `[disnans] chat transport: rust`

（Console は `Ctrl+Shift+I` で開く。）

従来の経路に戻す（逃げ道）:

1. `Ctrl+Shift+I` で開発者ツールを開き、Console で次を実行する:
   ```js
   localStorage.setItem('disnans.rustApi', '0');
   localStorage.setItem('disnans.rustChat', '0');
   ```
2. アプリを再起動する（フラグは起動時に1回だけ読む）。
3. Console が `http` / `js` になっていれば従来の経路。

Rust 経路に戻す:

```js
localStorage.removeItem('disnans.rustApi');
localStorage.removeItem('disnans.rustChat');
```

再起動する。読取とチャットは独立しているので、片方だけ `'0'` にしてもよい。

起動時に Rust 経路が使えなかった場合（コマンドがない、接続できないなど）は、**従来の経路へ自動で切り替えない**（二重送信を防ぐため）。
- チャットが接続できないときは、toast「チャットに接続できませんでした: …」が出る。接続バナーの「今すぐ再接続」で、もう一度接続を試す。
- 読取が失敗したときは、各画面の既存の表示になる（履歴は読めなかった旨、プラグイン一覧は「読めませんでした」、設定は読まれないまま）。

## 確認項目

見た目は仮の文言を含む。見た目の判断は利用者が行う。

### 基本の表示

- [ ] 起動直後に接続バナーが出て、接続後に消える。
- [ ] メインチャットの最新メッセージが表示される。
- [ ] 上へスクロールすると、過去のメッセージが追加で読み込まれる。
- [ ] スレッドを開くと、返信が表示される。
- [ ] 検索でメッセージが見つかる。
- [ ] 投稿者の名前・アイコン、未読の表示、設定のプラグイン一覧が表示される（「ユーザー一覧」という画面はありません。名前の表示に内部で使っています）。

### 送信（このブラウザ・アプリから）

- [ ] テキストを送ると、仮表示から実メッセージに変わり、仮表示が残らない。
- [ ] 返信を付けて送ると、返信先が正しく表示される。
- [ ] スレッドを開始して送ると、スレッドが作られる。
- [ ] 添付付きで送ると、添付が表示される。
- [ ] 通知なし（silent）で送ると、相手に通知が出ない（CLI の `watch` 側で確認）。

### 他の端末からの受信

- [ ] CLI で `disnans send "テスト"` を実行すると、アプリにすぐ表示され、通知が出る。
- [ ] 他の端末で編集・削除・リアクションすると、アプリに反映される。

### 切断と再接続

- [ ] サーバーを止めると、接続バナーが出る。
- [ ] サーバーを起動し直すと、自動で復帰し、履歴が取り直される。
- [ ] 「今すぐ再接続」を押すと、すぐ接続し直す。

### 送信失敗の表示（重要）

- [ ] サーバー停止中に送信すると、「送信できませんでした」と再送・取り消しが出る。その後に続く理由の文（例: 「チャットに接続していないため送信しませんでした」）も出る。再送は押すと送られる（サーバーを起動してから）。
- [ ] 送信ボタンを押した直後にサーバーを止める（結果が分からない状態）と、「送信できたか確認できません」と「確認したので消す」だけが出る。**再送ボタンは出ないこと**。
- [ ] 上の場合、サーバーを起動してから `disnans watch` 等で見て、同じ本文が**1件だけ**（または0件）であること。二重投稿がないこと。
- [ ] 送信の結果を受け取れなかったとき（まれ）は、「送信結果を確認できません」と「確認したので消す」だけが出る（再送は出ない）。

### 従来どおり動くもの（JS 側の接続が担当）

- [ ] 通話（参加・退出・画面共有）が従来どおり動く。
- [ ] プラグインの読み込みと、プラグイン間のイベントが従来どおり動く。
- [ ] 設定（表示の好み・通知）の変更が保存され、反映される。

### 無効化後

- [ ] フラグを消して再起動すると、Console が `http` / `js` になり、上の送信・受信が従来どおり動く。

## 既知の制限

- TLS は Rust 側が webpki（組み込みの証明書）を使う。OS の証明書ストアは使わないので、社内 CA の https サーバーでは接続できない場合がある（従来経路は WebView の設定に従う）。
- 通話・プラグイン・設定（prefs）は従来どおり JS 側の WebSocket を使う。チャットの接続が2本になる。
- 結果が不明（unknown）のメッセージは、後で履歴に出た同じ本文と自動では結び付かない。利用者が「確認したので消す」で消す。
- 送信コマンドが応答を返さなかった場合（コマンドが見つからない、IPC の失敗など）は、書込んだかどうか分からないので、安全側に結果不明として扱う（再送はしない）。
- 読取の Rust 経路は、リダイレクト（3xx）に従わない。通信のタイムアウトは 15 秒。
- 文言（送信失敗・結果不明・接続できない等）は仮。利用者の確認が必要。
- macOS は従来経路のまま（Rust 経路の対象外）。
- 見た目（配置・色）は変えていない。見た目の最終確認は利用者が行う。
