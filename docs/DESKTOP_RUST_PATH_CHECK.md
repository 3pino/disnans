# デスクトップ版 Rust 経路の実機確認（チェックリスト）

対象: Windows / Linux のデスクトップ版。読取（REST）とチャット（WebSocket）を Rust 経由にしたときの確認。
Rust 経路は既定で有効。従来の経路に戻すには、下の「有効化・無効化」の手順を使う。

## 有効化・無効化

Windows / Linux のデスクトップ版では、読取（REST）とチャット（WebSocket）の Rust 経路が**既定で有効**。
ブラウザ・macOS は従来の経路のまま。Android は読取・書込・添付だけ Rust 経路（チャットは従来どおり JS の WebSocket）。

確認するだけなら手順はない。アプリを起動し、次の2行が Console に出ていれば Rust 経路で動いている:

- `[disnans] api read transport: tauri`
- `[disnans] chat transport: rust`

（Console は `Ctrl+Shift+I` で開く。）

従来の経路に戻す（逃げ道）:

1. `Ctrl+Shift+I` で開発者ツールを開き、Console で次を実行する:
   ```js
   localStorage.setItem('disnans.rustApi', '0');
   localStorage.setItem('disnans.rustChat', '0');
   ```
2. アプリを再起動する（フラグは起動時に1回だけ読む）。
3. Console が `http` / `js` になっていれば従来の経路。

Rust 経路に戻す:

```js
localStorage.removeItem('disnans.rustApi');
localStorage.removeItem('disnans.rustChat');
```

再起動する。読取とチャットは独立しているので、片方だけ `'0'` にしてもよい。

起動時に Rust 経路が使えなかった場合（コマンドがない、接続できないなど）は、**従来の経路へ自動で切り替えない**（二重送信を防ぐため）。
- チャットが接続できないときは、toast「チャットに接続できませんでした: …」が出る。接続バナーの「今すぐ再接続」で、もう一度接続を試す。
- 読取が失敗したときは、各画面の既存の表示になる（履歴は読めなかった旨、プラグイン一覧は「読めませんでした」、設定は読まれないまま）。

## 確認項目

見た目は仮の文言を含む。見た目の判断は利用者が行う。

### 基本の表示

- [ ] 起動直後に接続バナーが出て、接続後に消える。
- [ ] メインチャットの最新メッセージが表示される。
- [ ] 上へスクロールすると、過去のメッセージが追加で読み込まれる。
- [ ] スレッドを開くと、返信が表示される。
- [ ] 検索でメッセージが見つかる。
- [ ] 投稿者の名前・アイコン、未読の表示、設定のプラグイン一覧が表示される（「ユーザー一覧」という画面はありません。名前の表示に内部で使っています）。

### 送信（このブラウザ・アプリから）

- [ ] テキストを送ると、仮表示から実メッセージに変わり、仮表示が残らない。
- [ ] 返信を付けて送ると、返信先が正しく表示される。
- [ ] スレッドを開始して送ると、スレッドが作られる。
- [ ] 添付付きで送ると、添付が表示される。
- [ ] 通知なし（silent）で送ると、相手に通知が出ない（CLI の `watch` 側で確認）。

### 他の端末からの受信

- [ ] CLI で `disnans send "テスト"` を実行すると、アプリにすぐ表示され、通知が出る。
- [ ] 他の端末で編集・削除・リアクションすると、アプリに反映される。

### 切断と再接続

- [ ] サーバーを止めると、接続バナーが出る。
- [ ] サーバーを起動し直すと、自動で復帰し、履歴が取り直される。
- [ ] 「今すぐ再接続」を押すと、すぐ接続し直す。
- [ ] 通話で音声が続いているあいだも、チャットのメッセージが抜けずに届く（取りこぼしがあっても、画面が読み直して埋まる）。バナーが「再接続しています…」のまま残らない。

### 送信失敗の表示（重要）

- [ ] サーバー停止中に送信すると、「送信できませんでした」と再送・取り消しが出る。その後に続く理由の文（例: 「チャットに接続していないため送信しませんでした」）も出る。再送は押すと送られる（サーバーを起動してから）。
- [ ] 送信ボタンを押した直後にサーバーを止める（結果が分からない状態）と、「送信できたか確認できません」と「確認したので消す」だけが出る。**再送ボタンは出ないこと**。
- [ ] 上の場合、サーバーを起動してから `disnans watch` 等で見て、同じ本文が**1件だけ**（または0件）であること。二重投稿がないこと。
- [ ] 送信の結果を受け取れなかったとき（まれ）は、「送信結果を確認できません」と「確認したので消す」だけが出る（再送は出ない）。

### 従来どおり動くもの

- [ ] 通話（参加・退出・画面共有）が従来どおり動く（通話はチャットと同じ Rust 接続で動く。下の「通話の確認項目」を参照）。
- [ ] プラグインの読み込みと、プラグイン間のイベントが従来どおり動く。
- [ ] 設定（表示の好み・通知）の変更が保存され、反映される。

### 無効化後

- [ ] フラグを消して再起動すると、Console が `http` / `js` になり、上の送信・受信が従来どおり動く。

## 編集・削除・リアクション・スレッド作成の確認項目（Rust 経路）

- [ ] 自分のメッセージを編集すると、本文が変わり、他の端末（`disnans watch` など）にも同じ内容が出る。
- [ ] 自分のメッセージを削除すると、消え、他の端末でも消える。
- [ ] リアクションを付けると、表示され、もう一度押すと外れる。他の端末にも反映される。
- [ ] メッセージからスレッドを開くと、スレッドができ、他の端末にも出る。
- [ ] サーバーを止めた状態で編集・削除・リアクションすると、「接続中ではないため送れませんでした」と出る。自動では再送されない（サーバーを起動しても勝手には送られない）。
- [ ] 送信の結果を確かめられないとき（送信直後にサーバーを止めるなど）は、「送信できたか確認できません。自動では再送しません」と出る。同じ操作を押し直すまで、勝手には送られない。
- [ ] 通話・プラグインの操作・設定の保存は、この変更の後も従来どおり動く（デスクトップではすべて Rust 経由）。

## 通話・プラグイン・セッション・画面共有の確認項目（Rust 経路）

### 通話の確認項目（Rust 経路。通話もチャットと同じ接続を使う）

- [ ] 通話に参加すると、参加者の一覧に出る。退出すると、一覧から消える（他の端末でも同じ）。
- [ ] 通話中に音声が相手に届く（双方向）。少し遅れることがある。映像・画面共有が届く。通話の中の画面（領域・ボタン）が従来どおり出る。
- [ ] 通話中に相手を外す（キック）と、外された側に通知が出て、通話から抜ける。
- [ ] 通話中にチャットの接続が切れると、「通話の接続が切れました。つながると自動で入り直します」と出る。切れているあいだの音声は届かないことがある（許容）。戻ると「通話の接続が戻りました」と出て、参加者の一覧が元に戻る（自動で入り直す）。
- [ ] 切れているあいだに通話の操作（ミュートなど）をしても、エラーは出ない（通話の状態は戻ったあとに反映される）。参加・退出の操作だけは、送れなかったと出る。
- [ ] 通話の映像の画質が、回線が細いときに自然に落ちる（極端に遅れない）。
- [ ] プラグインの一覧・読み込み・プラグイン同士のイベント（`plugin.emit`）が、相手の端末にも届く。
- [ ] セッション（ゲームなど）の作成・更新・セッションのイベント（`session.emit`）が、相手の端末に届く。
- [ ] サーバーを止めた状態でセッションやプラグインのイベントを送ると、「接続中ではないため送れませんでした」と出る（従来は接続が戻ってから送られた。今は送られない）。
- [ ] チャットが 401/403 などで止まったとき、バナーに「チャットに接続できません。30秒ごとに再試行しています」と出て、設定を直すと 30 秒以内に戻る。toast は最初の1回だけ。
- [ ] 同じく止まっているあいだ、プラグインのイベントや通話の参加は送れず、「送れませんでした」と出る（黙って消えない）。

## 書込・添付の確認項目（Rust 経路）

- [ ] Console に `[disnans] api write transport: tauri` が出る（読取と同じ経路）。
- [ ] 表示名を変えて保存すると、設定画面に新しい名前が出て、再起動後も残る。
- [ ] アバターを設定すると画像が変わり、「アバターを消す」で元に戻る。日本語のファイル名の画像でも設定できる。
- [ ] 設定（表示の好み）を変えると、再起動後も残る。
- [ ] スレッドのタイトル・アーカイブ・タグを変えると、一覧に反映される。
- [ ] 既読の位置が進み、再起動後も未読数が正しい。
- [ ] 通知のサンプル（設定の「サンプル通知」）が出る。
- [ ] 画像・ファイルを添付して送ると、添付が表示される。大きめのファイル（数MB）で進捗が動く。
- [ ] 添付の送信中に「中止」を押すと、すぐ止まり、添付が付かない。中止後に同じファイルを選び直すと上がる。
- [ ] 添付の送信に失敗したら、再送は自動では行われない（利用者が送信を押し直したときだけ上がる）。
- [ ] プラグインの公開・削除、プラグインのセッション作成・更新（ゲームなど）が従来どおり動く。
- [ ] サーバーを止めた状態で書込を行うと、エラーが出る（黙って成功しない）。サンプル通知・プラグインのメッセージ・セッション作成は、失敗時に「結果を確認できませんでした。二重投稿を防ぐため自動では再送していません」と出る。
- [ ] 上の結果不明の表示のあと、サーバーを起動してから同じ操作が二重に効いていないこと（サンプル通知は通知が2回出ていないか、セッションが2つできていないか）。

## Android の確認項目（読取・書込・添付の Rust 経路）

Android では、読取・書込・添付のアップロードは Rust 経路（既定で on）。チャット・通話・プラグインのイベントは従来どおり JS の WebSocket。Android の IPC は raw body を渡せないので、添付・アバター・プラグインの本体は base64 の文字列で渡す（大きいファイルほどメモリと時間を使う）。`disnans.rustApi` を `0` にすると従来の経路に戻る。

- [ ] アプリを開くと、一覧（チャンネル・メッセージ・ユーザー・スレッド・プラグイン）が読める。ページを戻る・進むと、読み直しても同じ内容。
- [ ] 証明書を使う https のサーバーに、接続できる（SSL_CERT_DIR の設定が効く）。接続できないとき、画面に理由が出る。
- [ ] メッセージを送る・編集する・削除する（チャットは JS の WebSocket で従来どおり）。送信後の表示は従来どおり。
- [ ] 画像（数 MB）を添付して送ると、送信できて表示される。進捗が出る。途中で中止すると止まる。
- [ ] 大きい添付（20 MB 前後）でも、アプリが固まらずに送れる（時間はかかってよい。固まったら記録する）。
- [ ] アバターを変更する・消すと、変わって見える（他の端末からも見える）。
- [ ] プラグインのアップロード（ファイルを選んで公開）が通る。失敗したときは理由が出る。
- [ ] `disnans.rustApi` を `0` にすると、読取・書込・添付が従来の経路（HTTP）に戻り、同じように動く。
- [ ] ブラウザ版（同じサーバー）と Android 版で、同じ一覧・投稿が見える。

## 既知の制限

- TLS は Rust 側が webpki（組み込みの証明書）を使う。OS の証明書ストアは使わないので、社内 CA の https サーバーでは接続できない場合がある（従来経路は WebView の設定に従う）。
- デスクトップ（Rust 経路）では JS 側の WebSocket を作らない。通話・プラグイン・セッション・設定の変更も、すべて Rust の接続を通る。ブラウザ・Android・Rust 経路を切ったときは従来どおり JS 側の WebSocket。
- 結果が不明（unknown）のメッセージは、後で履歴に出た同じ本文と自動では結び付かない。利用者が「確認したので消す」で消す。
- 書込（アバター・プラグイン公開・セッション作成など）も、Rust 経由で応答が返らなかった場合は、非冪等のものは「結果を確認できませんでした」として扱い、自動では再送しない。
- 送信コマンドが応答を返さなかった場合（コマンドが見つからない、IPC の失敗など）は、書込んだかどうか分からないので、安全側に結果不明として扱う（再送はしない）。
- 読取の Rust 経路は、リダイレクト（3xx）に従わない。通信のタイムアウトは 15 秒。
- 文言（送信失敗・結果不明・接続できない等）は仮。利用者の確認が必要。
- macOS は従来経路のまま（Rust 経路の対象外）。
- 見た目（配置・色）は変えていない。見た目の最終確認は利用者が行う。
