# 通話の標準の画面共有

状態: 採用。画面共有・カメラ共有は、通話と同じ本体の機能として持つ。旧 `screenshare` プラグインを本体に同梱する方式ではない。

## 所有者と境界

- `CallStore.screen` が共有の状態を所有する。参加者・参加／退出・再接続・受信イベントは、`CallStore` から直接渡す。プラグインの有効化や画面のマウントでは始めたり終えたりしない。
- 操作・通話内の映像・大きな閲覧画面・共有設定は Svelte の本体コンポーネント。プラグインの `addButton` / `addPanel` / 設定タブを介さない。
- 大きな閲覧画面（`ScreenShareViewer`）は、写真の拡大表示（`Lightbox`）と同じ `LightboxView`（ビューアー・上のバー・ノッチなどの安全域）に、ライブの映像を載せる。映像は `key` が同じ 1 件として渡し、フレームが変わっても拡大・移動を保つ。共有の閲覧では前後の切り替えとダウンロードは出さない。表示中は回転設定の「メディア」に含め、閉じる・共有終了・破棄で解除する。「縦固定」は解除しない。
- 配信側の映像も、受信側と共通の全幅のカードで通話画面の流れの中に表示する。右下の小さな重ね表示にはしない。カメラの自分の映像は消音のまま扱う。
- OS の画面取得と PiP の橋は `app/src/lib/media/`。本体用の型・例外を持ち、`PluginRuntime` やグローバルの `disnans` に依存しない。公開 SDK は互換のアダプターとしてこの橋を利用する。
- OS の継続取得は一つ。本体と拡張で所有者を分け、他方の取得を `stop` / `update` で変更しない。他方が使用中の開始は `busy` として断る。静止画プレビューは継続取得を始めない。

## 送受信

Android の画面共有は、動作確認されたネイティブ経路を維持する。前景・背景とも、分割送信・生存通知・参加者追加／問い合わせへの応答はネイティブ側で行う。JS が行うのは利用者の開始／停止操作と、前景のプレビューであり、同じ画像や状態を重複送信しない。

通話のセッション・世代・一回の取得に結び付ける。通話からの退出・取得終了・別の通話への変更で終了する。同じ通話の一時的な再接続では待機し、別の通話へ取得を引き継いだり、許可なしに取得を再開したりしない。Android による取得終了条件は変更しない。

Windows の画面取得、Linux の portal / PipeWire、カメラの取得と送信は既存の方式を維持する。設定やカメラの切り替えのために音声を開き直さない。取得選択中の退出や停止、古いカメラ／トラックの完了が、新しい取得を停止しないように扱う。

`screen.frame` / `screen.state` / `screen.query` と画像片 `{f,i,n,d}` は維持し、旧プラグインを使う他のデバイスとも送受信する。相手の単位はユーザー ID ではなく通話の peer。同じユーザーの複数デバイスをまとめない。

## 減色と圧縮

256 色は固定の RGB332 格子ではなく、フレームの色分布からメディアンカットで代表色を選ぶ。標本は最大 8192 画素、パレットは最大 256 色、画素の対応付けは 5 bit × 3 チャンネルのキャッシュで上限を設ける。JS・Android・Linux で分割・丸め・同点の規則を揃え、共通の試験データで比較する。フルカラー・グレースケール、送受信の形式とネイティブ中継の所有者は変えない。

代表色を画像に合わせると色の誤差を減らせる一方、画像によっては固定格子より符号化サイズが増える。通信量が常に減るとはしない。`app/scripts/screen-codec-check.mjs` は合成画面について実際の PNG / WebP のサイズ・RGB 誤差・処理時間を測る（実機の性能や実際の通話の測定ではない）。既存の帯域制限と画質・間隔の調整を維持する。動画コーデックへの移行は行わず、既存クライアントとの画像フレーム互換を保つ。

## 設定と旧プラグイン

FPS・画質・色数はデバイス設定の `screenShare` に保存する。Rust の設定定義で正規化し、未設定は `null` とする。旧 `disnans.plugin.screenshare.data` の値は、サーバーのデバイス設定を読んだ後、標準側が未設定の場合に一度だけ取り込む。旧値は消さず、標準側ですでに選択した値は上書きしない。

新しい本体は、配布済み・開発用のどちらでも旧 `screenshare` の実行を抑止する。旧プラグインの無効化設定は、標準機能を無効にする設定ではない。共有の開始は常に利用者の明示操作であり、移行や起動時には取得しない。旧クライアント向けのサーバー配布物は削除しない。

## 検証の境界

状態・分割／組み立て・非同期の取消・設定移行・二重起動防止は偽物のメディアとサーバーの試験で確認する。Android の既存ネイティブ経路も SDK ビルドと試験を維持する。実機の画像・音・背景動作や最終的な見た目は別の確認であり、自動試験だけで成功としない。
