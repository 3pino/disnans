# CLI/TUI と共通クライアント基盤

要件は [`SPEC_cli_tui.md`](../SPEC_cli_tui.md)、通信契約は [`API.md`](API.md) と `crates/shared` を参照。ここでは実装の境界と段階を整理する。

## 最初の実装範囲

7ステップのうち、まずステップ1の土台を作る。共通ファイルと読み取りAPIは後続ステップのための基盤であり、GUI の保存先・通信をこの段階で切り替えない。

- `crates/client-core` (`disnans-client-core`): 接続先の解釈、REST の読み取り、共通設定・下書きファイル。
- `crates/cli` (`disnans-cli`、実行ファイル `disnans`): 引数、設定、読み取りコマンド、安全な端末向け出力。
- `app/src/lib/sharedStorage.ts`: 将来のファイル移行を検証する非同期アダプター。まだ起動処理に組み込まない。
- 一時データの開発サーバーを使う結合テスト。サーバー本番データや利用者の設定を使わない。

`send` / `watch`、WebSocket の再接続、TUI、GUI の実際の移行、インストーラへの同梱は後続ステップ。未実装のコマンドを使えるものとして公開しない。この土台だけでは P0 完了とはしない。

## 担当と統合境界

| 担当 | 所有する実装 |
|---|---|
| helper-1 | `crates/client-core/`: URL・REST・共通ファイル基盤 |
| cli-tui | `crates/cli/` の本体: CLI と後続の TUI |
| helper-2 | GUI の保存・通信アダプターと後続の Tauri 橋 |
| helper-3 | `crates/cli/tests/`、結合試験・CI・後続の配布 |
| chief | 共通インターフェースの調整、workspace/lockfile、統合・検証 |

ルートの Cargo workspace に core と CLI を追加する。`app/src-tauri` は独立 workspace のまま、GUI 移行時に core を相対 path 依存として追加する。Tauri 用 lockfile はその時点で更新する。

## 通信と認証

- whois を実行するのはサーバー。クライアントに Tailscale のユーザー偽装や独自の認証処理を追加しない。
- CLI の `--dev-user` は `DISNANS_DEV=1` の開発サーバー用。恒久設定や本番の認証情報にはしない。
- 接続先は GUI と同様に IP・ホスト名・HTTP(S) URL を扱う。NFKC、前後の空白除去、HTTP スキーム補完、末尾スラッシュ除去を共通化する。CLI 独自の IP allowlist は設けない。
- ブラウザー GUI の空の接続先は同一オリジンを意味する。CLI にはこの意味がないため、未設定なら明示的に失敗する。
- core の URL は HTTP(S) の正しい URL として解析し、認証情報・query・fragment を含む接続先は拒否する。GUI 側の検証統一は移行時に行う。サーバーの base path は保持する。
- REST は `disnans_shared` の型を返し、HTTP エラーの status/code/message を保持する。画面や翻訳、終了コードへの変換は呼び出し側の責務。
- Svelte の状態管理、タイムライン、通知、描画は TypeScript に残す。ブラウザー開発版と Android の通知サービスは当面既存経路を使う。

### 後続の WebSocket 契約

- `hello` を受けてからメッセージを送信する。送信結果の相関は同じ接続の `client_id` を使う。
- `message.created` は確定を示す。切断・タイムアウト・確定を保証できないエラーは「成否不明」とする。サーバーは DB commit 後にエラーを返す可能性もあるため、すべての `error` を未投稿確定とは扱わない。
- 自動再送やオフラインでの無条件キュー投入をしない。サーバーには同一 `client_id` の重複排除の保証がない。
- イベント購読と送信結果の待機が互いのイベントを奪わない設計にする。
- 再接続は通信層が担当し、接続世代・状態を通知する。切断中のイベント復元は保証せず、呼び出し側が REST で表示中の履歴を再取得する。
- `watch` は診断を標準エラーへ出す。原始イベントの対象範囲と欠落通知の機械向け契約は WebSocket 実装前に確定する。

### GUI の通信切り替え

現在は通常のチャットと通話が同じ JS WebSocket を使う。Rust 側の接続を足すだけでは安全な移行にならない。

- 接続世代、`hello`、通常イベント、送信結果、通話メンバーシップそれぞれの所有者を明示する。
- 同じ投稿を新旧経路から送らず、イベントを画面へ二重反映しない。再接続時の再取得も一本化する。
- 通話 PCM・画面共有の高頻度イベントは、Rust↔JS 橋で性能を測る前に移さない。
- ファイルアップロードの進捗・中断、DOM プラグインなど P0 外の処理は、移行できる契約が整うまで既存の TS 実装を保持する。

## 共通ファイル

| 用途 | Linux | Windows |
|---|---|---|
| 設定 | `$XDG_CONFIG_HOME/disnans`（未設定時 `~/.config/disnans`） | `%APPDATA%/disnans` |
| 下書き | `$XDG_DATA_HOME/disnans`（未設定時 `~/.local/share/disnans`） | `%LOCALAPPDATA%/disnans` |

テスト・明示的な隔離用の上書きは `DISNANS_CLIENT_CONFIG_DIR` / `DISNANS_CLIENT_DATA_DIR`。絶対パスを指定し、空や相対パスの明示指定はエラーにする。保存先が決められない場合もカレントディレクトリへ黙って保存しない。サーバーの `DISNANS_DATA_DIR` とは分ける。CLI のテストは両方を一時ディレクトリへ指定する。

- 接続先と下書きを分ける。下書きは接続先サーバー・ユーザー ID・場所（main/thread）で分離し、生の ID をそのままパスへ使わない。
- 同一下書きは後から保存した内容を優先する。プロセス間ロックの中で読み取り・更新・同じディレクトリの一時ファイルへの保存・置き換えを完結する。時計の時刻ではなく保存の順で決める。
- 古い全体スナップショットで別の下書きを消さない。JSON 破損や未知の schema は黙って初期化せず、既存のデータを保全してエラーを返す。
- 専用ディレクトリとファイルを Unix では私有権限で作る。Windows は利用者のプロファイル配下とアクセス権を確認する。
- 同期ファイル API はブロッキング I/O。Tauri の非同期コマンドからは blocking 用の処理へ分離する。

### localStorage の移行

Windows/Linux の Tauri GUI の接続先・下書きだけが対象。prefs の正本は従来どおりサーバー。通話設定・プラグイン・テーマ・ナビゲーションなど GUI 専用状態を一緒に移さない。

1. 対象サーバー・ユーザーが分かってから旧値を読む。旧下書きはサーバーをキーに含まないため、別サーバーへ無条件に割り当てない。
2. 共有ファイルに既存値があれば優先する。移行のために CLI が保存した値を上書きしない。空の保存値と「未保存」を区別する。
3. 書き込みを読み戻して検証する。途中の失敗で旧値を削除したり、完了マーカーを立てたりしない。
4. 成功した場合だけ正本を切り替える。失敗時は旧 localStorage を保持して従来経路へ戻す。

共有ファイルへの保存成功と GUI の即時反映は別の契約。将来の起動・フォーカス・設定変更時の読み直しで接続先の変更を検出する。編集中の本文を外部更新で無条件に差し替えない。

## 検証と後続の配布

- core 単体: URL、HTTP/JSON エラー、ファイルの schema・排他・権限・原子的更新、移行用の既存値優先。
- CLI 単体: 引数、終了コード、stdout/stderr 分離、JSON と端末制御文字の安全化。
- 結合: 一時 DEV サーバー・CLI サブプロセスで設定共有と REST 読み取りを確認。WS・GUI 橋の相互反映は実装段階で追加する。
- workspace の test/clippy/fmt、app の check/test/build を統合時に実行する。
- CLI/TUI の同梱はステップ5で Windows NSIS と Linux deb に追加する。PATH の既存値、更新・削除、新しく開いたシェルからの起動を検証する。AppImage の PATH 自動登録は約束しない。
- 見た目・端末の操作感・実機動作の最終確認は利用者へ依頼し、AI が直接見た目を判断しない。
